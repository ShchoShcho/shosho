# ShoSho

WPF-застосунок для локальної колекції медіа. База даних — SQLite через Entity Framework Core 10.
Встановлювати PostgreSQL, створювати сервер, користувача або пароль більше не потрібно.

## Запуск

Для розробки потрібні Windows і .NET 10 SDK:

```powershell
dotnet run --project src/ShoSho.UI
```

Під час першого запуску програма автоматично створює каталог
`%LOCALAPPDATA%\ShoSho` та файл `shosho.db`, а міграції створюють таблиці.
Наступні запуски відкривають ту саму базу й застосовують нові міграції, якщо вони є.
Розташування бази не залежить від робочої папки або папки встановлення програми.
Кожен обліковий запис Windows має власну колекцію.

Для користувачів можна зібрати комплект із .NET Runtime (приклад для Windows x64):

```powershell
dotnet publish src/ShoSho.UI -c Release -r win-x64 --self-contained true -o publish
```

Передавайте всю папку `publish`; запуск — через `ShoSho.UI.exe`.

## Що змінено

- Видалено залежність Npgsql та PostgreSQL-параметри з `appsettings.json`.
- Запуск UI, стандартний контекст і фабрика EF використовують спільне налаштування SQLite.
- Початкову міграцію та snapshot переведено на типи SQLite. Це початкова схема для нової SQLite-бази, а не міграція даних із PostgreSQL.
- Збережено автоматичний `MigrateAsync`, без ручного налаштування таблиць.
- Дати записуються й читаються як UTC; GUID, український текст і статуси зберігаються через EF.
- Файли бази та журнали виключено з Git.

У `src/ShoSho.UI/appsettings.json` стандартний рядок:

```json
{ "ConnectionStrings": { "DefaultConnection": "Data Source=shosho.db" } }
```

Відносний шлях рахується від `%LOCALAPPDATA%\ShoSho`. Можна вказати абсолютний шлях
до іншого локального файлу в папці з правами запису. За відсутності конфігурації
використовується стандартний шлях. Фабрика команд `dotnet ef` також використовує
стандартний шлях; для іншої бази передавайте `--connection` явно.

## Дані та резервні копії

Наявна PostgreSQL-база залишається без змін. Автоматичного імпорту немає:
після переходу відкриється нова порожня локальна колекція. Для перенесення старих
записів потрібні окремі експорт та імпорт із збереженням ID, текстів, статусів і UTC-дат.
Не видаляйте стару базу до перевірки перенесення.

Для резервної копії закрийте всі екземпляри ShoSho та скопіюйте файл `shosho.db`.
Якщо поруч залишилися `shosho.db-wal` або `shosho.db-shm`, копіюйте їх разом із базою.
Відновлюйте також із закритою програмою. Оновлення файлів програми не видаляє колекцію.
Файл бази не зашифрований. Спільної серверної колекції та синхронізації між комп'ютерами немає.

SQLite підходить для локального застосунку, але має обмеження типів та зміни схеми:
[документація Microsoft](https://learn.microsoft.com/en-us/ef/core/providers/sqlite/limitations).
Історичні звіти в `docs/week*` описують попередні етапи з PostgreSQL.

## Перевірка

```powershell
dotnet build ShoSho.slnx --disable-build-servers -m:1
dotnet build tests/ShoSho.SqliteSmoke --disable-build-servers -m:1
dotnet run --project tests/ShoSho.SqliteSmoke --no-build
```

Перевірка створює окрему тимчасову SQLite-базу, застосовує міграції двічі,
перевіряє відповідність snapshot, CRUD, повторне відкриття, Unicode, UTC та сортування.
Користувацькі дані вона не змінює.
