# Відповідність документації — 30.10.2026

Перевірено `week1`–`week4`, README та поточні моделі, контекст EF, міграції, WPF-вікна й команди. Це зіставлення з репозиторієм, а не підтвердження виконання всіх початкових вимог.

| Вимога | Стан |
| --- | --- |
| Створення, перегляд, редагування, видалення картки | Реалізовано; видалення з підтвердженням, редагування через окрему чернетку. |
| Назва, опис, тип, URL/шлях обкладинки | Реалізовано. Автоматичний пошук метаданих не реалізовано. |
| Статуси, теги та фільтрація | Реалізовано. Відновлено врахування текстового `SearchTagFilter`, який перестав діяти після додавання вибору тегів. |
| Рейтинг 1–5, відгук для завершеного контенту | Узгоджено через `Core.Services.ReviewRules`: перевірки в редакторі та перед записом. Раніше редактор дозволяв змінювати відгуки для будь-якого статусу. Старі враження не стираються при зміні статусу. |
| Сітка карток | Реалізовано. На прохання користувача редагування, повний опис і теги перенесено в деталі; головна картка залишається компактною. |
| PostgreSQL | Замінено на SQLite за свідомим рішенням. Документацію сховища, розгортання й резервних копій актуалізовано. |
| MVVM і три проєкти | Часткова відповідність початковому плану: UI/Core/Infrastructure є, але більшість операцій з EF залишаються у MainViewModel. Окремих репозиторіїв немає. |
| Нормалізація | Є таблиці тегів, зв’язків і відгуків. Залишається legacy-поле `MediaItems.Rating`, яке дублює оцінку відгуку. Потрібна окрема міграція для усунення дублювання. |
| Реєстрація, авторизація, хешування паролів | Не реалізовано. SQLite не означає автоматичного виконання або скасування цієї початкової MVP-вимоги. Зараз колекція належить профілю Windows; облікових записів застосунку немає. |
| Офлайн | Дані локальні; завантаження ще не кешованих HTTP-постерів потребує мережі. |
| Кешування | Є локальний кеш; немає окремої політики очищення/ліміту розміру. |
| DPI 100/125/150% | Не підтверджено ручними перевірками на всіх масштабах. |
| Єдиний інсталятор, автоматичні backup | Не реалізовано. Є `dotnet publish` і ручне копіювання локальних файлів. |
| Синхронізація, соціальні функції, парсинг метаданих | Залишаються планами, не поточними можливостями. |

Додатково виправлено nullable-попередження у формі додавання та блокування повторного видалення під час збереження. Схему робочої бази ця перевірка не змінює.

Регресійні сценарії: відхилення зміни відгуку для незавершеного запису; дозволене редагування завершеного; збереження відгуку при поверненні до «Ін прогрес»; закриття чернетки без запису; фільтрація; SQLite-міграції та збереження старих даних. Команди запуску наведено в README.
